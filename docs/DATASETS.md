# Datasets

## What is used

| Dataset | Licence | Used for | In this repo? |
|---|---|---|---|
| **MVTec AD** (15 categories, 5,354 images) | CC BY-NC-SA 4.0 (non-commercial) | All reported metrics; anomaly models; YOLO-seg training | **No.** Downloaded by script; `datasets/` is git-ignored |
| Magnetic Tile, NEU-DET, VisA | see their pages | Downloader support only; **not used for any reported number** | No |
| Synthetic images in tests | generated in code | Unit tests of metrology, tracker, decision | Generated at test time |

**Licence consequence:** models trained on MVTec AD inherit its non-commercial terms. A commercial deployment must retrain on the customer's own images (the continuous-learning module exists for this).

**Real vs synthetic:** every metric in `backend/storage/reports/` comes from real MVTec AD images in the held-out test split. No synthetic or augmented image is ever scored. Simulated *production context* (machines, shifts, dates) is generated by `scripts/simulate_production.py`; those rows carry `is_synthetic=True` and are labelled SIMULATED in the UI.

## Reproduce

```bash
python3 ml/datasets/download_hf.py --dataset mvtec --out datasets/mvtec_ad      # ~4.9 GB, resumable
ml/.venv/bin/python ml/datasets/prepare_mvtec.py --root datasets/mvtec_ad --out datasets/prepared
```

The download mirror is the Hugging Face copy `foersben/mvtec-ad`. `prepare_mvtec.py` writes `datasets/prepared/manifest.json` with every image's split, class and SHA-256.

## Split (seed 2026)

One shared split is used by every model, so all numbers are on the same unseen images.

- `fit`: MVTec `train/good`. Normal-only; fits the anomaly memory banks. 20% of it is held back inside fitting to set the good-only threshold.
- `train` / `val` / `test`: defect images, split 60/20/20 **per (category, defect kind)** so every kind appears in every split. `test/good` is divided between `val` and `test` so false-reject rate is measured on unseen good parts.
- `unknown_val` / `unknown_test`: defect kinds mapped to `None` below. They never enter supervised training and test whether the anomaly model catches defects it was never shown.
- **Cross-split duplicates (SHA-256): 0.**
- Thresholds are chosen on `val` + `unknown_val`. `test` + `unknown_test` are touched only for final scoring.

## Label mapping

The five platform classes are SCRATCH, CRACK, DENT, DISCOLOURATION and DIMENSIONAL_ANOMALY. MVTec kinds are mapped to them in `ml/datasets/label_map.py`. **This mapping is a modelling decision, not ground truth**: for example `hazelnut/hole` → DENT and `tile/oil` → DISCOLOURATION are judgement calls.

Defect instances per class (one image can have several):

| class | train | val | test |
|---|---|---|---|
| SCRATCH | 129 | 44 | 44 |
| CRACK | 83 | 27 | 28 |
| DENT | 47 | 16 | 14 |
| DISCOLOURATION | 137 | 46 | 44 |
| DIMENSIONAL_ANOMALY | 106 | 36 | 34 |

DENT has the fewest examples; expect its per-class score to be the weakest and least stable.

Withheld (unknown) kinds include: combined, faulty_imprint, rough, thread, toothbrush/defective, metal_contamination, metal_nut/flip, zipper teeth and fabric defects, hole (carpet), print, fold, cable_swap, missing_cable, missing_wire, damaged_case, misplaced, pill_type.

## Known limitations

- MVTec images are studio-lit, centred, one part per image. Real lines have motion blur, glare and part overlap; field accuracy will be lower until retrained on line images.
- MVTec "dents" are few; DENT results are low-confidence.
- No physical dimensions are available in MVTec, so millimetre accuracy is validated only on synthetic images with known geometry (`tests/test_industrial_units.py`), not on real parts.
